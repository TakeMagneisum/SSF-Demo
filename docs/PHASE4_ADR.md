# Phase 4 architecture decision record — display preferences and reflow

**Status:** implemented and offline-validated, not browser-verified or human-accepted. Source: supplied completed Phase 3 ZIP only. No production/deployment/provider changes. No baseline rewrite.

## Decisions

1. **Static shared controls + one small first-party preference script and CSS layer.** Native labeled selects and a nonmodal `details` disclosure minimize custom focus behavior. The generator `scripts/phase4-template.py` checks exact markup, inserts controls near the menu, and embeds the same script and CSS in the standalone 404. No runtime component fetch, backend, framework or accessibility overlay. Alternatives rejected: duplicating manually edited controls across pages (drift), framework/overlay (extra dependency, privacy and accessibility risk), replacing every stylesheet (unbounded Phase 4 risk). 18 primary + six styled legacy/error pages including root 404. Redirect-only local guide pages and research HTML are untouched except preexisting assets; they are not claimed to have independent preference controls. Original static links and route semantics remain.
2. **Separate appearance from Calm View.** Reuse the established Calm color palette for dark appearance; preserve original Calm-only decorative suppression, denser presentation and motion policy. Explicit System/Light/Dark controls the preference; active Calm View intentionally uses dark and reduced motion regardless of appearance until turned off. Explain this in settings; maintain `ssf-calm-view` and language keys. The effective appearance uses `matchMedia`, with live changes, and no inference of geographic jurisdiction. Higher contrast strengthens semantic borders/text and links; forced-colors uses browser system colors. Reduced motion honors OS regardless of stored selection. All controls are opt-in and reversible. CSS uses both semantic tokens and compatibility selectors for existing components rather than unsafe body-only recoloring. The default works without JS (original readable light presentation and navigation; user-facing preferences hidden when initialization cannot run). No-JS OS dark palette is not implemented; OS reduced motion and forced colors remain CSS-driven where supported.
3. **One allow-listed non-sensitive storage record.** `ssf-display-preferences-v1`: `appearance` system/light/dark; `text` standard/large/larger; `spacing` standard/relaxed; `contrast` system/high; `motion` system/reduced; `density` comfortable/compact. Defaults are first values. No location, query, guide, handout, or timestamp fields. Invalid or malformed records resolve to defaults; blocked storage uses in-page state. Reset removes only this key (not language, Calm View, selection or print data); local changes persist when permitted. Bfcache and system media changes update state, storage events update the display settings; no new external request, analytics or telemetry. Existing browser storage and provider behavior unchanged. Privacy notice updated.
4. **Native disclosure in flow, narrow-screen reflow.** No dialog trap, Escape/Close returns to the disclosure summary, menu opening closes settings, existing Menu Escape behavior retained. Header/content sidebar no longer sticky; avoid nested state/county list scrolling (more document length is a deliberate tradeoff). Controls wrap and 44px minimum for key targets where practical; at narrow widths and large text, grids become single column; reading text uses root rem scaling 125%/150% and relaxed spacing. Browser zoom still works independently. Existing map zoom/reset is unchanged; no pan redesign. SVG outlines + textual selection/list labels; forced-color support. No claim that every small SVG area is physically 44px; list alternatives remain necessary.
5. **Handout recovery without overlays.** Narrow/large-text tray is in normal document flow (primary and styled nested finder tray moved before resource grid). Selected-card review button lets the visitor open the same original print preview locally; on return, restore origin focus and scroll, and clear returns to checkbox when available. No resource changes. Original session-storage key, QR encoder, PDF implementation and official URL semantics retained. Screen-only appearance CSS prevents newly introduced dark colors from leaking into print; actual native printing, PDF and QR scanning remain unverified. Legacy copies may differ; preserve until tested redirect plan.
6. **Targeted Spanish improvements.** Added Spanish display-setting UI labels, core map coverage/selection and failure messages, guide counts, ZIP limitation wording. Geographic/provider names stay as sourced in the new map logic; translation remains partial and only on pages already supporting language selection. Do not imply professional translation or independent review. No emergency content or source metadata changed. No new postal data.

## Boundaries and verification

The existing `assets/styles.css` contains a later default paper/muted token override (#f4f0e5/#536b67); the original brand reference values remain in the source. Static contrast check uses effective default tokens and selected explicit dark pairs. 17 opaque pairs pass thresholds, but CSS cascade on real components, all hover/disabled/urgent combinations, gradients, images, zoom, screen readers and forced-color rendering have not been verified. Actual Chrome navigation was policy blocked at the first page in both initial/final attempts; no restriction bypass. See `PHASE4_TEST_RESULTS.md` for evidence. Map simulation harness now scopes its country option parsing to the actual country select and leaves preference testing to its dedicated simulation (no weakening of original route assertions).
