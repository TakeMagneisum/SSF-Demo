# Phase 5 architecture decision record

Status: implemented and offline-validated; browser, AT, native printing, hosting and human acceptance open. Source: supplied Phase 4 demo ZIP only. No new geography, live source review or deployment.

## Observed baseline

`guide.js` built each card in full using DOM APIs, with priority → featured → title sort for category browse; keyword/phrase/category score then priority for situation matches, capped at nine. `urgent.js` independently classified emergency before suicide before violence; `area.js` resolved a selected guide and its jurisdiction. Canonical records have 3,487 placement-level IDs, title, categories, keywords, source, scope, summary, next, URL; 2,841 dialing fields, 2,870 phone-display fields, 36 addresses, 3 public intake source fields, 37 urgent flags. There is no uniform explicit service-type/eligibility/cost schema. `next` can contain critical limits, so no automatic classification, extraction, abbreviation or hiding of it. Guide `reviewed` is a provenance date, not current availability. Discovery's 13 topics and ZIP associations are independent, unchanged. The seven full resource scripts are still needed on the main directory by the current handout catalog; home/map load only coverage metadata. Handout key `ssf-print-selection-v1` stores JSON-stringified [area ID, resource ID] pairs in session storage; native printing and direct PDF use existing preview/QR code. `ssf-selected-area`, country, language, Calm and Phase 4 display settings remain separate. No new storage.

## Decisions and alternatives

1. Use existing DOM renderer and native `details`/`summary`, not a component framework or custom disclosure. Always show heading, source/scope, category, urgency (when flagged), summary, full next step, exact contact/address, official link, guide-level source date and print selection. Optional transit, preparation and correction links inside details. No new provider/service-type label inferred. Existing sourced wording distinguishes referral or direct help when available. A discovered mixed phone/text display where the stored dial value is explicitly text-only is displayed without a voice action; no alternate target derived. `resource.id` used in runtime dataset, scoped by existing guide; no new record URL contract or synthetic ID. `phase5.css` uses Phase 4 tokens, relative type and list option, print retains critical fields. Existing detail state and list layout stay in page memory. Expansion controls act only on current results; no page rerender for expansion. Filter changes rebuild cards while keeping expansion IDs and handout choices; focus stays on topic or returns there when a chip is removed. Search answer and results title are focus targets.
2. Maintain the original urgency classifier and exact routing tables. New small vocabulary file is a presentation-only set of narrowly scoped phrases and misspellings; no aggressive fuzzy matching, semantic AI, or changes to original record text. Original scoring retained with extra stopwords and aliases, and all positive scores shown rather than unexplained nine-result truncation. No certainty claim from relevance. Emergency fallback limited to explicitly US/PR guide or explicit emergency metadata, otherwise neutral. An invalid guide has no search or default US records. Existing guide-level emergency banners remain. Current browse OR filters are intentionally a separate mode from situation search: selecting a topic clears the search rather than silently filtering urgent results; UI explains this. Individual topic removal, counts and zero-close-match fallback keep the guide and handout state. `?need=` legacy single-category links (including `mental-health`) still initialize; subsequent explicit filtering/search clears that parameter, never writes sensitive text or topics to URL/history/storage. Browser Back/Forward across actual pages follows original route handling; local ephemeral state may be lost on reload or language change. Browser cache/form restoration beyond application control is not guaranteed; `autocomplete=off`, unnamed situation input and disabled submit until handler initialized prevent native form leakage. No attempt to persist situation for Back/Forward. Existing public `?area=`, `?topic=`, map/ZIP routes unchanged.
3. Copy only fixed public preparation text/questions on deliberate click; no new editable personal forms. Native clipboard where permitted, manual-selection instructions otherwise. Existing call/travel scripts retained, added questions derived from existing guidance and plain-language definitions. Cards link into standalone prep routes; handout preview copies its existing script without adding a paragraph to PDF's intro selector. No changes to QR encoder, handout.js or sheet-pdf.js. No external requests from preferences/search/prep code. Correction mailto still includes only public resource/guide metadata and blank issue prompt. Direct map link remains user-initiated with existing public address only.
4. Kept all three finder HTML paths; older `assets/find-help.html` lacks newer handout/full-registry dependencies in original archive, so guard missing handout API instead of crashing. Do not claim this older duplicate equivalent or delete/redirect until proven compatibility. Updated all three form privacy guards and optional controls; nested full finder gets copy control. Updated shared Spanish labels for new controls; translation remains partial (dynamic counts, category labels, source-language scripts, some legacy pages); no independent language review. No new flags or live-source claims.

## Rollback and risks

Use supplied Phase 4 ZIP for atomic rollback. Revert guide.js, shared i18n/version tokens and three finder templates/prep pages together; remove new phase5 scripts/CSS/tests and CI step. Never regenerate immutable snapshots. Browser policy prevented actual visual, keyboard, forced-colors, print, screen reader and hosted acceptance. Positive-score keyword results can be broad and are not a diagnosis/eligibility evaluation. All source fields and routes are unchanged, but legacy duplicates and real browser behavior need independent testing. No release signoff.
